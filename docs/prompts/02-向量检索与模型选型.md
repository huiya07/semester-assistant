# 功能：向量检索与嵌入模型选型（2026-10-25）

## 目标
把切片向量化入库，并能按问题召回带页码的片段。

## 关键提问（原文摘录）
1. 「先用 Chroma 默认模型跑通，再评估中文效果。」
2. 「每步跑完实测。」——不要写完就宣称完成。

## 第一轮：默认模型跑通，但中文是废的

用 Chroma 自带的 `all-MiniLM-L6-v2`（英文模型）跑通链路，然后实测三组查询：

| 查询 | 最佳 distance | 是否正确命中 |
|---|---|---|
| 英文问「多少个注意力头」 | **0.39** | ✅ p5（`h = 8 parallel attention layers`） |
| 中文问同一件事 | 0.81–0.87 | ❌ 返回位置编码、参考文献 |
| 麻婆豆腐（库外） | 0.87–0.88 | —— |

**中文与「完全无关」的分数几乎相同**，说明这个模型对中文没有任何判断力。课程资料是中文的，必须换。

## 第二轮：换 BGE，但测试设计错了

换成 `BAAI/bge-small-zh-v1.5` 后复测中文提问，distance 从 0.81 降到 0.58，但**仍然没命中 p5**。

定位：这不全是模型的锅——**我用英文文档 + 中文提问，考的是跨语言检索**。而真实场景是中文资料 + 中文提问。这是测试设计的错误，不是实现的问题。

改用中文样本（`习题1.1 画勾题解析.pdf`）重测：第 1 命中就是正确答案，distance 0.49。

## 第三轮：发现混库污染
中文正确命中 0.49，但排在 2–5 名的英文无关片段是 0.54–0.56，**差距只有 0.05**。
原因：英文文档被中文模型映射后，向量落在与中文不同的区域，噪声天然靠得很近。

## 踩到的接口坑
Chroma 1.x 不再只调用 `__call__`，而是分别调用 `embed_documents` / `embed_query`。
只实现 `__call__` 会报 `AttributeError: ... has no attribute 'embed_query'`。
另外顺手加上了 BGE 官方的查询指令前缀（`为这个句子生成表示以用于检索相关文章：`），只在 query 侧加、文档侧不加。

## 结论
1. **嵌入模型必须按资料语言选**，英文模型对中文没有判断力。
2. **验证要用真实场景的语料**：跨语言检索不能代表同语言检索的效果。
3. **混语言混库会互相污染**，产品上应当**按课程分组检索**（选某门课再提问），既符合真实场景，也天然避开噪声。
4. 初步阈值：`distance < 0.6` 可作为「有依据」的候选线，需在问答阶段用实际回答验证。

## 实测结果
- 英文对英文：正确页 distance ≈ 0.44–0.46
- 中文对中文：正确页 distance ≈ 0.49
- 均能稳定进第 1 名

# 演示视频分镜脚本（最终版）

> 目标：6 分 40 秒左右，1080p 16:9，含 ≥2 分钟 AI 协同过程复现。
> 旁白按 4.5 字/秒估算时长；标注「静默」的段落只留画面与字幕。
> 录屏用 OBS（`D:\maybe\personal\obs-studio\bin\64bit\obs64.exe`）。
> 相关：`视频制作记录.md`（工具链与踩坑）、`比赛要求摘要.md`（硬性要求原文）。

## 一、时长预算

| 段落 | 时长 | 对应评分项 |
|---|---|---|
| 开场：问题与定位 | 40 秒 | 解题有效性 25% |
| 功能演示 | 1 分 50 秒 | 实用性 25% |
| **AI 协同：一次完整迭代** | **2 分 35 秒** | 过程可复现 25% + 意图控制 20% |
| 架构与工程 | 1 分 | 工程质量 15% |
| 收尾 | 30 秒 | —— |
| **合计** | **约 6 分 35 秒** | 留 1 分钟余量到 8 分上限内 |

## 二、录屏前必须做的准备（录之前逐条打勾）

- [ ] **窗口拉成 16:9**：浏览器窗口拉到约 1920×1080 的比例，不要全屏铺满 2560×1600 的屏幕
- [ ] **关闭通知**：Windows 通知、微信、QQ、TG 全部静音或免打扰
- [ ] **清桌面**：桌面图标不进入画面（用最大化窗口规避）
- [ ] **资料库准备**：库里放 1–2 篇带课程名的资料，不要留测试残留
- [ ] **作业日期**：把至少两条作业的日期挪到「今天起两周内」，让周视图和「接下来两周要交」有内容
- [ ] **Claude Code 换干净会话**：避免左侧会话列表出现其它项目名
- [ ] **切换脚本就位**：
  - 切到「有 bug 的版本」：`git apply D:/Lc/.tmp/buggy-lock.patch`
  - 切回「修复版」：`git apply -R D:/Lc/.tmp/buggy-lock.patch`
  - （录 AI 协同段之前必须先切到 bug 版并重启服务）
- [ ] **试录 30 秒**：确认分辨率、麦克风（如用）、画面没有黑边

## 三、分镜

### 第 1 段　开场（0:00–0:40）

**画面**：应用主界面全貌，鼠标不点，轻微移动即可。

**旁白**（约 165 字，36 秒）：

> 课程资料散在 PPT、教材和讲义里，复习的时候常常只记得老师讲过，却怎么也翻不到在第几页。课表和作业，又散在另一个地方。学期助手把这两件事放进同一条时间轴上：问资料里的问题，答案永远带着页码出处；找不到就说找不到；顺便告诉你这周该做什么。这是一个本地运行的个人工具，不需要联网部署，上传 PDF 就能开始。

### 第 2 段　功能演示（0:40–2:30）

#### 2-1　上传资料（0:40–0:55）

**操作**：点「添加资料（PDF）」→ 选择 PDF → 课程下拉选一门课 → 点「加入资料库」。

**旁白**（约 55 字，12 秒）：

> 先把课程资料传进来。上传的时候可以标一个归属课程，后面检索就能按课程缩小范围。

#### 2-2　提问与带出处的回答（0:55–1:20）

**操作**：输入「标准差用来衡量什么」→ 回车 → 等答案逐字出现。

**旁白**（约 90 字，20 秒）：

> 提问之后，答案里的每一个结论后面都带一个方括号编号，表示这个说法来自检索到的第几段材料。模型只允许根据这些片段作答，不允许自己补充。

#### 2-3　出处与原文（1:20–1:50）

**操作**：点开引用卡片 → 展开「命中片段」→ 点「查看原页」→ 显示 PDF 原页面。

**旁白**（约 110 字，25 秒）：

> 点开出处的编号，先看到命中的原文片段；再点查看原页，直接跳到 PDF 的那一页。这一步是这套系统最核心的设计：结论不是让用户相信模型，而是让用户能自己核对。

#### 2-4　找不到就说找不到（1:50–2:05）

**操作**：清空输入框，问「太阳系有几颗行星」。

**旁白**（约 60 字，14 秒）：

> 如果资料里根本没有，它不会编一个答案，而是直接说明没检索到相关内容。这是三层防线里最外面的一层。

#### 2-5　周视图（2:05–2:30）

**操作**：切到「这周该做什么」。

**旁白**（约 100 字，22 秒）：

> 另一半是这周该做什么：现在是第几教学周，这一周有哪些课，两周之内有哪些作业要交。作业块可以点开看完整标题，课表和作业都可以导入自己的版本。

### 第 3 段　AI 协同：一次完整的迭代（2:30–5:05）

> 这一段是评委看的重点。关键是「出问题 → 人怎么发现 → 怎么让它改」，不是「AI 顺利写完」。
> 录制时这是**真实发生**的过程，不是演示；中途的等待、来回都是真的，后期只做时间压缩。

#### 3-1　问题出现（2:30–2:50）

**操作**：回到资料问答，问一个问题 → 回答正在逐字输出时，点「停止」→ 再问同一个问题 → 出现「上一个问题还在回答中，等它说完再问」→ 等十几秒再问，仍然如此。

**旁白**（约 85 字，19 秒）：

> 录屏的时候遇到一个卡死：点了停止之后，再提问就一直提示「上一个问题还在回答中」。等了一分多钟也没恢复，只能重启服务。

#### 3-2　交给 AI，先定位不急着改（2:50–3:10）

**操作**：切到编辑器里的 Claude Code 会话，输入：

> 点停止之后再提问，一直提示「上一个问题还在回答中」，重启服务才好。先定位原因，先别改代码。

**旁白**（约 70 字，16 秒）：

> 我把这个现象交给 Claude Code。第一句故意只让它定位，不让它动手改——先确认原因对不对，再决定怎么修。

#### 3-3　AI 定位到根因（3:10–3:50）

**画面**：Claude Code 读 `api.py` 的流式端点，指出锁是在生成器的 `finally` 里释放的。

**旁白**（约 120 字，27 秒）：

> 它找到的是这一段：并发守卫用的是同一把锁，请求进来先拿锁，流式生成器跑完在 finally 里释放。问题在于，客户端中途断开的时候，Starlette 并不保证把生成器读完，finally 就没有执行，锁一直没有放回去。所以后面每一个请求都被挡在外面。

#### 3-4　确认根因，再下修复指令（3:50–4:05）

**操作**：人看代码，确认「只有 finally 一条释放路径」，然后输入修复要求。

**旁白**（约 55 字，12 秒）：

> 看过代码，确认它说的没错：释放只有这一条路。于是我让它换一种不依赖生成器一定跑完的方式。

#### 3-5　改动（4:05–4:35）

**画面**：代码改动出现在编辑器里——加 `released` 标志位、`release()` 函数、`finally` 里改成调用它，再给 `StreamingResponse` 挂 `background=BackgroundTask(release)`。

**旁白**（约 100 字，22 秒）：

> 它的改法是再加一层兜底：除了生成器自己的 finally，响应结束后再由 BackgroundTask 释放一次；用一个标志位防止两次重复释放。这样无论生成器有没有跑完，锁都会被放回去。

#### 3-6　复测（4:35–5:05）

**操作**：重启服务 → 重复同样的操作：提问 → 中途点停止 → 立刻再问 → 正常回答出来。

**旁白**（约 90 字，20 秒）：

> 重启服务，用完全相同的操作复测：提问，中途点停止，然后立刻再问一次。这次马上就能答出来，不用等，也不用重启。

### 第 4 段　架构与工程（5:05–6:05）

**画面**：终端跑测试，或切到技术文档里的架构图。

**操作（推荐）**：终端执行 `pytest tests/test_smoke.py -q`，让 20 项通过的输出滚过屏幕。

**旁白**（约 250 字，55 秒）：

> 工程上有三件事值得说。第一，抗幻觉不是靠一句提示词，而是三层：检索层用距离阈值把不相关的问题挡在调用模型之前；提示层约束只能引用给定片段；后处理层再用正则检查答案里的编号是不是真的存在。第二，按课程检索用的是软分组——选了一门课之后，未分类的资料仍然会被检索到，不会因为选了课反而漏掉东西。第三，测试是后端 20 项、前端 14 项，每次改完都要跑一遍。

### 第 5 段　收尾（6:05–6:35）

**画面**：GitHub 仓库页，或回到应用界面。

**旁白**（约 110 字，24 秒）：

> 从第一行代码到现在，这个项目的每一次改动、每一个决定、每一次踩坑都留了记录，仓库里能看到完整的演进过程。学期助手解决的是一个很小的问题：让课程资料真的能被查得到。

## 四、录制建议

1. **分段录，不要一口气**：功能演示录一条，AI 协同录一条，收尾录一条。任何一段不满意单独重录。
2. **AI 协同段是真的在跑**：Claude Code 输出可能要几十秒到几分钟，不要中途停。后期用变速把等待压掉，保留「人能看懂发生了什么」的节奏。
3. **不要在录屏里露出真实姓名、学校、学号、手机号**。上传的资料用仓库自带的示例讲义，不要用真实课件。
4. **桌面和浏览器标签页**：只留一个标签页，避免出现其它项目名。

## 五、后期流程（录完由小鸦做）

4. **遮挡**：顶栏、桌面图标、其它项目名
5. **输出**：1920×1080 / 30fps / MP4，控制在 6:00–7:30
6. **上传**：B 站，标题与简介备好

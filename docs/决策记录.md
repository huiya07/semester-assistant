# 决策记录（ADR）

> 每条都是**已经讨论并定下**的结论。新会话不要重新发起讨论，除非发现新证据能推翻它——那时在下面追加一条，不要改写旧的。

## D1：选 Vibe Coding 赛道，不选 LLM 科研助手赛道
**日期：** 2026-10-23
**理由：** LLM 赛道要求六大模块全覆盖、通过官方测试集（含 541 页教材解析、扫描件 OCR）、Docker、公网在线演示、决赛答辩占 30%，是团队三个月的工程量；Vibe Coding 50% 权重在「过程可复现 + 意图控制」，正是灰鸦的强项，且不要求部署。
**代价：** 放弃了一个技术深度更高、含金量可能更高的赛道。

## D2：项目选题 = 学期助手（课程资料 RAG + 学期视图）
**日期：** 2026-10-23
**理由：** 真实痛点（灰鸦是学委）、数据可得且可脱敏、演示效果好、模块可切碎、赛后能继续用。
**差异化点：** 答案带页码级溯源、检索不到就说找不到、学期视图把散乱信息串成产品闭环。

## D3：不做多 Agent 架构
**日期：** 2026-10-23
**理由：** 26 天单人，多 Agent 容易变成一堆半成品互相超时。评分要的是「清楚地在控制 AI」，不是架构图上有几个框。单链路 + 严格约束 + 完整记录得分更高。

## D4：前端 Vite + React + Tailwind + shadcn-ui，不用 Next.js
**理由：** 不需要 SSR 和 Node 后端，Next.js 只增加构建复杂度。shadcn 组件 AI 生成质量稳定。

## D5：不部署公网
**理由：** 本赛道不要求在线演示（那是 LLM 赛道的要求），演示用录屏完成。省掉服务器成本与评审期可用性风险。

## D6：学期视图数据全部自造/脱敏
**理由：** 花名册是 key 密级、学生个人信息不得进入公开仓库。课表与作业数据全部虚构。

## D7：embedding 用本地 bge-small-zh-v1.5，退路是 Chroma 内置模型
**理由：** 全部本地、零 API 成本。附加代价：sentence-transformers 会带 2–3GB torch，venv 放 D 盘。装不动就退 Chroma 默认 `all-MiniLM-L6-v2`（中文效果打折可接受）。

## D8：Prompt 链留档（比赛要求至少 3 条核心功能迭代）
**实际留档四条，对应四个真实的设计/调试过程：**
- `01-解析与切片.md` —— 切分质量从 92% 硬切修到 80% 句末结尾
- `02-向量检索与模型选型.md` —— 默认英文模型对中文失效，换成 BGE；混库污染
- `03-问答与抗幻觉.md` —— 三层防线；正确答案被挤出前 5，top_k 5→8
- `04-学期视图.md` —— 作业稀疏建模、课名想当然、砍掉章节进度映射

**说明：** 原计划写「绑在 Task 2 / 4 / 7」，实际是 2 / 3 / 4 / 7 四条。以此条为准。

## D9：计划按 26 天排期，落后时的砍单顺序
**顺序：** 先砍学期视图的复习建议（保留周课表）→ 再砍 UI 打磨 → **Task 4（问答溯源）和 Task 9（视频+文档）绝不砍**。

## D10：产品的独特性定位（2026-10-25，回答「是不是重复造轮子」时定）
**承认：** RAG 链路是最成熟的轮子（AnythingLLM / Dify / RAGFlow / FastGPT / Khoj / Onyx 全是成品），「课程资料喂进去让学生问」也已有人做（Uedu 类 AI 助教）。技术层面确实是重复。
**但赛道不评技术新颖度**：五维权重里没有创新度这一项，命题背景原话是「代码编写成本趋近于零，考的是定义问题、产品设计、架构编排、指挥 AI」。
**唯一硬差异：时间轴 × 知识库的交叉**。现成产品的数据结构里没有「第几周」，因此答不了「下周高数作业要用哪一章」「第三章是上周学的吗」这类跨课表/作业/文档的问题。
**两条半硬差异**：① 可信度三态（有依据 / 依据不足 / 无依据）+ 披露检索范围；② 主动推送（学期视图）vs 被动问答。
**不算差异只算基线**：带页码溯源（必须有，但不当卖点）。
**风险：** 独特性只有被看见才存在。演示脚本必须有一个「跨三张表才能答」的镜头。
**若只保留一个功能：** 保留「这周该做什么」——同时体现时间轴、主动姿态、真实痛点，演示最直观。
**技术减法：** 不追混合检索 / rerank / 多路召回 / GraphRAG，用 Chroma + 直接调 API 的最小实现，代码保持几百行且能逐行讲清。


## D11：前端组件库由 shadcn-ui 改为 open-claude-ui（补充 D4）
**日期：** 2026-11-10
**背景：** D4 定的是「Vite + React + Tailwind + shadcn-ui」。实际开发中发现 shadcn 需要逐组件生成，
而 `Caho1/open-claude-ui`（MIT，1739 stars）直接提供 30 个成品组件 + 183 个设计令牌 + 纯 CSS 版本，
对「快速做出完成度」更有利。
**采纳：** 拷 4 个组件（ConfirmationDialog / CdsButton / ScrollFadeContainer / StatusIndicators）
与设计令牌，**配色整体替换**（陶土橙 `#d97757` → 靛蓝 `#3f61a3`），不复制其视觉语言。
**理由：** 该库是高保真还原 Claude 桌面端的产物，外观照搬会被判缺乏原创性；
只借「结构化灰阶 + 克制阴影」这套工程方法。
**代价：** 组件内部的几个私有 token（`shadow-2xs` 等）未开源，需要自己补齐定义。

## D12：删除 Streamlit 早期界面
**日期：** 2026-11-10
**决定：** 迭代期间前端有两套（Streamlit 快速验证 + React 正式版），最终版删除 Streamlit。
**理由：** 早期版本不是给评委看的；仓库里两套前端会让「工程质量」这一项显得冗余。
复现路径改为 `setup.ps1` 一键完成（装依赖 → 构建前端 → 启动）。
**代价：** 失去「一条命令立刻看到界面」的简易路径，复现需要 Node.js 环境。
**连带：** 移除 streamlit 依赖时 `python-multipart` 被一并带走（那是 FastAPI 文件上传必需的），已显式加回。

## D13：按课程分组采用「软分组」
**日期：** 2026-11-10
**决定：** 文档可标归属课程，检索时可限定课程，但**未分类文档始终参与检索**。
**理由：** 如果严格按课程过滤，加入功能之前入库的老资料会瞬间查不到，用户会以为数据丢了。
实测确认：严格过滤下旧数据的确是 0 命中。
**实现：** `where={"$or": [{"course": 选中课程}, {"course": ""}]}`；
启动时给历史切片补 `course:""`（Chroma 的空值匹配不到「字段不存在」的记录）。

## D14：抗幻觉判定从「二元」改为「能答多少答多少」
**日期：** 2026-11-10
**背景：** 原 prompt 是「片段中没有能回答问题的信息就只输出 NO_ANSWER」。
实测问「四个指标分别是什么、各自适合什么场景」时，四个定义片段里都有，
但「场景」覆盖不全 → 模型整条拒答。
**决定：** 改为「只要包含问题任何一部分答案就如实回答，没涉及的方面单独一行写『资料未覆盖：…』，
只有完全无关才 NO_ANSWER」。
**验证底线：** 改后「太阳系有几颗行星」仍然 not_found，抗幻觉未被削弱。
**新增认知：** `not_found` 有三种原因 —— 资料真没有 / 检索没召回 / 判定标准过严。
三者修法完全不同（无解 / 调 top_k / 调 prompt），统一当成「抗幻觉生效」会持续误判。

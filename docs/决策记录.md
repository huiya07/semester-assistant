# 决策记录（ADR）

> 每条都是**已经讨论并定下**的结论。新会话不要重新发起讨论，除非发现新证据能推翻它——那时在下面追加一条，不要改写旧的。

## D1：选 Vibe Coding 赛道，不选 LLM 科研助手赛道
**日期：** 2026-10-23
**理由：** LLM 赛道要求六大模块全覆盖、通过官方测试集（含 541 页教材解析、扫描件 OCR）、Docker、公网在线演示、决赛答辩占 30%，是团队三个月的工程量；Vibe Coding 50% 权重在「过程可复现 + 意图控制」，正是灰鸦的强项，且不要求部署。
**代价：** 放弃了一个技术深度更高、含金量可能更高的赛道。

## D2：项目选题 = 学期助手（课程资料 RAG + 学期视图）
**日期：** 2026-10-23
**理由：** 真实痛点（灰鸦是学委）、数据可得且可脱敏、演示效果好、模块可切碎、赛后能继续用。
**差异化点：** 答案带页码级溯源、检索不到就说找不到、学期视图把散乱信息串成产品闭环。

## D3：不做多 Agent 架构
**日期：** 2026-10-23
**理由：** 26 天单人，多 Agent 容易变成一堆半成品互相超时。评分要的是「清楚地在控制 AI」，不是架构图上有几个框。单链路 + 严格约束 + 完整记录得分更高。

## D4：前端 Vite + React + Tailwind + shadcn-ui，不用 Next.js
**理由：** 不需要 SSR 和 Node 后端，Next.js 只增加构建复杂度。shadcn 组件 AI 生成质量稳定。

## D5：不部署公网
**理由：** 本赛道不要求在线演示（那是 LLM 赛道的要求），演示用录屏完成。省掉服务器成本与评审期可用性风险。

## D6：学期视图数据全部自造/脱敏
**理由：** 花名册是 key 密级、学生个人信息不得进入公开仓库。课表与作业数据全部虚构。

## D7：embedding 用本地 bge-small-zh-v1.5，退路是 Chroma 内置模型
**理由：** 全部本地、零 API 成本。附加代价：sentence-transformers 会带 2–3GB torch，venv 放 D 盘。装不动就退 Chroma 默认 `all-MiniLM-L6-v2`（中文效果打折可接受）。

## D8：三条 Prompt 链绑在 Task 2 / 4 / 7
**理由：** 解析与切片、问答与引用校验、学期视图——这三个功能各有一次真实的纠偏过程，最经得起评委看。不做事后补录。

## D9：计划按 26 天排期，落后时的砍单顺序
**顺序：** 先砍学期视图的复习建议（保留周课表）→ 再砍 UI 打磨 → **Task 4（问答溯源）和 Task 9（视频+文档）绝不砍**。

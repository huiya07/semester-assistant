## 流程

1. **先录后配**：操作耗时不可控，硬按旁白节奏录很别扭。录屏时静音、不说话。
2. **旁白分段**：按画面动作分七段，每段 TTS 生成独立 mp3，用 `adelay` 按时间点叠加。
3. **字幕**：从旁白文本按标点切句，按语速（4.5 字/秒）分配时长，`subtitles` 滤镜烧录。

## 踩过的坑（重要）

### 1. ffmpeg 多处 overlay 会失败
`split=3` + 两个 overlay 串起来 → `libx264 Task finished with error code: -22`，输出 0 字节。
**解法：分次编码**，每次只做一个 overlay，用 `enable` 表达式支持多时间段。

### 2. boxblur 半径不能接近区域高度
`crop=1360:92` + `boxblur=30:5` → 失败；改成高度 120 就正常。
**规则：区域高度至少是 blur 半径的 3 倍以上。**

### 3. `-shortest` 会截断视频
音频比视频短时，`-shortest` 把视频尾部切掉（3:09 → 2:48）。**合成时不要加。**

### 4. 字幕烧录的 Windows 路径
`subtitles='D:/...'` 报 `original_size: Invalid argument`。
**解法：把 SRT 复制到当前目录，用相对路径** `subtitles=sub.srt`。

### 5. 时间轴换算
用户给的时间点是「成品视频时间」，不要再减剪掉的 14 秒。**这个错误导致遮挡错位两轮。**

### 分辨率的坑

屏幕是 2560×1600（16:10），1080p 是 1920×1080（16:9），比例不一致。直接缩会变形，直接裁会切内容。

- **推荐**：录之前把窗口拉成接近 16:9（约 1920×1080），录完直接压 1080p，无黑边。
  界面本身是居中布局，16:9 完全够用。
- 备选：录完上下补黑边（2560×1440 → 1920×1080），保住画面但两侧有黑边。

### AI 协同段要展示什么（评委看的重点，占「过程可复现性 25%」）

主办方点名两种：**Prompt 生成模块** 或 **引导修顽固 Bug**。关键不是「AI 顺利写完」，而是：

1. 人给一句真实、简短的需求
2. AI 生成实现（过程要看得见）
3. **中间出了问题 → 人怎么发现的 → 怎么让它改的** ← 这一段是「引导」的唯一证据
4. 改完复测通过

光看顺利路径不算协同，必须有一次真实纠偏。
